# Memory — 2026-04-15

## What we implemented

### Language switching (product copy + UI strings)

- Locale allowlist: `en`, `hi`, `gu`
- Locale persistence: `locale` cookie, set on switch and read on load.
- Product copy translations live in:
  - `public/locales/{locale}/products.json` (per-locale map: `slug -> translated fields`)
- UI strings live in:
  - `public/locales/{locale}/common.json`
- Product merge:
  - Base catalog product comes from `src/data/products.ts`
  - Locale override is applied via a deep merge + token replacement pipeline:
    - `mergeProductWithLocale` in `src/lib/catalog/merge.ts`
    - wrapped by `getTranslatedProduct` in `src/lib/i18n/product-translations.ts`
  - Product detail page always merges **from catalog** so switching locales is consistent.

### Locale module (single source of truth)

- `src/lib/locale/index.ts`
  - `ALLOWED_LOCALES`, `parseLocaleCookie`, `setLocaleCookie` (adds `Secure` on HTTPS)
  - `LOCALE_CHANGE_EVENT` (event name constant)
  - `localeToHtmlLang` + `DocumentHtmlLang` updates `document.documentElement.lang`

### QR system (printed QR must never change)

- Canonical printed QR format (contract): `{QR_BASE_URL}/p/{slug}`
- QR entry route: `src/app/p/[slug]/page.tsx`
  - resolves locale: cookie → browser language → default
  - writes locale cookie
  - redirects to `/products/{slug}`
- QR generator:
  - Script: `scripts/generate-qr.mts`
  - Output folder: `public/assets/qr/{slug}.svg`
  - Uses slugs from `src/data/products.ts` (single source of truth)
- Docs: `docs/qr.md`
- Env template: `.env.example` (`QR_BASE_URL`)

### Safety tooling

- Catalog validation:
  - `npm run catalog:check`
  - Script: `scripts/check-catalog.mts`
  - Checks missing slugs, duplicates, and non-canonical slug formatting.

## Bugs fixed

- `public/locales/{locale}/products.json` files were invalid JSON (two concatenated root objects), causing translations to silently fall back to catalog (English). Files were merged into single valid JSON objects.

## Operational rules (do not break)

- Once a QR is printed, the product `slug` must not change.
- Printed QR encodes `/p/{slug}` only; `/p/{slug}` must remain supported forever.
